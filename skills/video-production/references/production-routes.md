# 制作路线

根据观众最需要看见的东西选择画面来源。已有工程可直接复用渲染器，先用一段样片确认字体、素材解码和声画同步。需要方向预览时，选最有代表性的静帧和最难实现的运动，各做一个。

## 素材混剪

1. 给素材建清单，记录路径、来源、许可、画幅、是否有可用原声。检查源文件时长和编码，命名相似的片段用唯一素材 ID 查找。
2. 先看缩略图或接触表找到候选，再播放候选段，逐个记录看点和源片入点、出点。连续动作保留交代位置的前一拍和结果落定的后一拍。
3. 先排出有起承转合的主段，再加文字、音乐和转场。现场声能说明动作时保留，音乐为说话或关键原声让出音量。
4. 横素材进竖版时，先取完整主体，再考虑跟踪裁切、分屏或在竖版底板上放完整横画面。有证据意义的细节、图表和署名要能在最终构图中看见。

## 口播剪辑

1. 用口语写短句。每句给一个画面任务，例如展示动作、展示证据、解释关系或交代时空。讲到具体数字或结论时，优先用能核对的原始资料和画面。
2. 沿用用户指定或已经通过试听的音色。新音色先试听包含专名、数字和长句的片段。朗读文本可为发音调整拼写，屏显和字幕仍用正式写法。
3. 逐句录制或对整段旁白做对齐，测得实际时间。以旁白锚定口播轨，让画面在关键字或动作附近变化。句太长可拆两镜，场景切换可跨句延续，保留观众读图的时间。
4. 真素材展示发生过什么，代码图解说明素材里看不见的机制。画面只用于气氛或举例时，旁白和画面要让观众能辨认它的用途。

## 代码动画

- 先画出状态前后两帧，再确定变化顺序、动线和重点颜色。解释因果时，让原因先出现，再让结果发生，给重要状态留可读的停顿。
- 用 HTML/CSS、SVG、Canvas 或工程已有引擎实现。标题、数据和字幕用可编辑的文字图层。用 `seek(t)` 或等价的时间轴入口按输出时刻渲染，提前等待字体、图片与视频加载。用种子控制随机效果，避免导出帧依赖系统时间。
- 长视频按章组织生成器，共享样式和时间轴数据，保持每章可独立预览。已有 HyperFrames 工程时，沿用它的合成规则与校验命令。浏览器素材冻结时，先确认媒体是否可解码，再用项目支持的编码制作代理文件。
- 需要复渲时，保存帧率、字体、素材版本、种子和运行命令。同一时刻重复渲染并检查画面，计时型交互逻辑与导出入口共享场景状态。

## 网页仿真录制

- 把模型状态、可交互操作与拍摄机位分开。用可靠资料确认外形和动作，先证明动作能稳定触发和复位，再补细节。若需交付网页，提供操作说明和本地预览命令。
- 镜头表为每镜记录机位、初始状态、触发帧和要看的变化。常用三镜组合是全景交代场景、特写指出关键部位、慢动作展示过程。快动作先试录再确认时长和慢放倍率。
- 系统录屏适合样片。要复拍时固定种子、输入、机位与初始状态，用 Playwright 或现有浏览器工具逐帧推进仿真，等当前帧渲染完再截图。需要状态历史的仿真按固定步长从初始状态运行，或用经过验证的状态快照跳转。
- 用 30 fps 导出时，原速每输出帧推进约 1/30 秒。8 倍慢放每输出帧推进约 1/240 秒，仍按 30 fps 编码。物理求解器可以保留更细的固定内部步长。看第一帧、命中帧和结束帧，并在片中按需标慢放倍率和仿真假设。

已有[变色龙仿真教程](https://github.com/songofhawk/science-video-from-simulation/blob/main/SKILL.md)可用作这一条路线的完整例子。
