# 成片验收与发布

从实际交付的 MP4 做检查。先在短段确认渲染和排版，再逐个验收正式导出的语言与画幅。按时间码记录问题、修复和复查结果。

## 技术检查

下面的命令用到 `ffmpeg` 和 `ffprobe`。替换 `video` 为实际成片路径。检查画幅、帧率、视频与音频编码、时长与有声版的音轨是否符合任务要求。

```sh
video='final/assets/videos/topic.zh-CN.1080x1920.mp4'

ffprobe -v error -show_streams -show_format -of json "$video"
ffmpeg -hide_banner -nostdin -v error -xerror -i "$video" \
  -map 0:v:0 -map '0:a?' -f null -
```

全片解码有助于发现坏帧和读档错误。检查音轨与画面时长时，允许符合设计的停幅、淡出和编码填充。普通网页或平台通用版可从 MP4、H.264、`yuv420p`、AAC 和 `faststart` 起步，最终以要求的规格为准。

对有声片，测成片的综合响度和真峰值，并试听说话、音乐进入和安静段。按项目的目标调整，留出峰值余量。

```sh
ffmpeg -hide_banner -nostdin -i "$video" \
  -map 0:a:0 -vn -af ebur128=peak=true -f null -
```

## 审片

- **镜头。** 抽首帧、核心动作前中后、转场两侧、最拥挤的一镜和末帧。接触表适合整体扫视，快速动作、闪黑、字幕残留和衔接要播放对应时间窗再确认。
- **字幕与构图。** 用手机尺寸查看字号和换行，核对是否挡住主体或落进平台界面区。打开各画幅版分别检查。多语版核对图中标签和单位、标题卡、封面以及二维码旁的文字。
- **混音与旁白。** 播放开头、包含专名和数字的段落、原声与旁白重叠段、最后一句。检查漏念、读音、爆音、音乐盖住人声和片尾被切断。转写差异列为回听点，技术日志与听感检查分别记录。
- **事实与授权。** 从原出处核对数字、时间、引用和画面对应关系。检查公开素材的授权、署名与必要的 AI 内容标识，把授权信息留在素材清单中。

抽帧示例。把 `3.2` 换成待检查的时间点。接触表示例按每秒一格查看开头 8 秒，后续段可换起点。

```sh
mkdir -p work/qa
ffmpeg -hide_banner -v error -y -ss 3.2 -i "$video" \
  -vf 'scale=360:-2' -frames:v 1 -update 1 work/qa/phone-3.2s.png
ffmpeg -hide_banner -v error -y -i "$video" \
  -vf 'trim=duration=8,fps=1,scale=240:-2,tile=4x2' \
  -frames:v 1 -update 1 work/qa/opening-sheet.png
```

## 发布清单

以用户指定的账号和平台为准，每个目标记录语言、画幅、成片、封面、标题、简介、字幕或声明、当前状态和作品链接。核对平台当前接受的时长、画幅、封面规格和声明项。用预览检查平台实际生成的裁切与字幕。双语互链如需等两条都上线，可先记录作品编号，再补链并验证。

在多平台工作流里，可把视频号、抖音、小红书、B 站、YouTube 和 X 各列一行。版本分工可以是国内投中文，B 站优先横版，YouTube 中英独立发布，X 用英文主帖串联中文回复。这个分工可按项目和账号受众调整。

状态用实际界面或接口证据核对。若提交结果不确定，先查作品管理页或已知作品编号，再决定是否重试，避免重复发片。
