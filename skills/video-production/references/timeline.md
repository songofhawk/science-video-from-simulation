# 时间轴与版本

把本片每镜的任务与素材对应关系保存在一个可编辑的时间轴里。已有剪辑工程或结构化镜头表时沿用。新项目可以先用 Markdown 分镜，进入自动渲染再转成 JSON 或引擎的工程格式。

## 分镜字段

| 字段 | 填什么 |
| --- | --- |
| 镜头 ID | 稳定标识，例如 `s07`，用来对照口播片段、反馈和渲染帧 |
| 画面任务 | 这一镜观众要看懂的变化或发现 |
| 旁白与字幕 | 朗读稿、屏显文字、实际起止点，可为长句拆字幕 |
| 画面来源 | 素材 ID 与源片入点、出点，或动画场景与事件 |
| 成片位置 | 由剪辑工程、旁白或音乐锚点确定的成片入点、出点 |
| 审片重点 | 要保留的主体、口型、关键动作、图注或署名 |

### 结构化示例

以下是一条带旁白的镜头。秒数统一使用秒，区间采用左闭右开。`edit` 和 `narration` 是从成片开头计时，`source` 从源文件开头计时。

```json
{
  "id": "s07",
  "purpose": "让观众看见第二个摆锤开始摆动",
  "edit": {"in": 12.4, "out": 16.0},
  "narration": {"text": "这时候，第二个摆锤开始动了。", "in": 12.55, "out": 15.3},
  "captions": [{"text": "第二个摆锤开始摆动", "in": 12.55, "out": 15.3}],
  "source": {"assetId": "take-02", "in": 4.1, "out": 7.7}
}
```

- 逐句配音时，从文件实际时长和设定的空隙计算后续起点。整段录音可用带时间戳的转写辅助定位，再校正长停顿、数字与专名。按实际帧率把画面切点落到帧边界，音频和字幕保留自己的时间精度。
- 复用同一源片时记清每次选区和变速。先确认源片区间有效，再决定剪短、放慢、用静帧还是补镜。用经过核对的源片时间码回查引用和署名。
- 对能反复渲染的字幕，将换行与时间从主时间轴导出。按短语切行，保持专名、单位与数字完整。烧录和独立字幕都基于同一份时序，依目标带上需要的格式。

## 版本与修订

- **横版和竖版。** 同语言共享音轨与叙事时序，按画幅设置镜头安全构图、图标位置、字号、字幕换行和封面。每版至少查看开场、全片信息最密的一镜和片尾。
- **双语。** 每种语言单独写口播、对齐字幕、核验读音和画面内文字。语速差异会改变镜头长度。为关键动作重新定入点和停留；素材太短时补画面或重新录制。逐个核对数字、单位、引用和来源署名。
- **局部修订。** 先在镜头表用稳定 ID 标记改动范围。只改画面时复用已确认的旁白、时间轴和混音，需要验证音轨完全相同时比对文件或音频包哈希。只改一句话时复用其他句音频，重算受影响的切点、字幕和后续段落。重审改动区和两边的接点。
- **成片命名。** 可用 `topic.zh-CN.1080x1920.mp4` 与 `topic.en.1920x1080.mp4`。每个版本的封面、字幕、时长和目标平台在交付清单里对应到具体文件。
